# 本地控制台版本验证记录

固件标识：care-portal-1。以下仅记录实际执行过的检查，不把浏览器模拟接口测试当成手机与开发板端到端测试。

## 已执行

- ESP-IDF 6.1 编译、链接及分区容量校验通过。
- 程序大小 0x12f3c0，程序分区 0x1f0000，剩余约 39%。未改动 NVS 与 PHY 分区位置。
- COM7 烧录成功，写入数据哈希校验通过。
- 通过串口重启开发板并观察启动日志：8 MB PSRAM 测试通过，屏幕初始化、Wi-Fi APSTA、DHCP 和网页服务均启动，观察窗口未见 panic、看门狗重启或应用初始化错误。
- 实际热点 AI-Care-E421，热点地址 192.168.4.1。
- 重启日志显示 Storage ready: boot=2, retained events=1，证明此前启动事件已写入并能在重启后读取；不是断电压力测试。
- 使用本机 GCC 对实际检测器源码验证：12 帧基线、候选连续计数中断、候选触发、恢复阈值、重置采样计数。
- 对实际配置/输入函数验证：参数上下界、UTF-8 表单解码、空字节/坏转义/溢出拒绝及 JSON 转义。
- 使用本机 Edge 无界面浏览器与模拟 API 验证：错误密钥、登录、开始监测、手动报警倒计时/激活/取消、参数表单、网络表单、历史 JSON 导出。
- 手机页面 390 像素视口检查：无脚本异常，页面内容宽度为 390，无整体横向溢出。

## 仍需实机手机验收

1. 手机接入热点、用屏幕 Key 登录，检查状态能持续更新。
2. 测试屏幕报警、取消、再开始监测，核对开发板屏幕和网页一致。
3. 摄像头固定后完成基线，主动开启视频共享；停止监测/报警/关闭共享后应停止输出视频。
4. 测试 5 分钟共享到期以及同时观看时取消/停止命令仍可执行。
5. 输入实际家庭 Wi-Fi，检查真实连接/IP；错误密码和路由器断电后热点应仍可用。
6. 修改参数，等待事件写入后重启，确认参数和历史保留。
7. 设置 5 分钟屏幕关怀，检查提醒、确认和重新计时。
8. 较长时间运行，检查内存、按键、摄像头和网络稳定性。
9. 对着板载麦克风拍手或说话，检查网页“麦克风已就绪”和音量峰值变化；这只验证采音，不代表语音识别。

没有测试真实模型准确率、外接环境传感器、音频/蜂鸣器、云推送或 OpenVela；这些功能尚未接入。浏览器测试没有修改电脑 Wi-Fi 配置，也没有将摄像头图像上传到外部服务。

构建、烧录和启动日志分别在本地 build/portal_build.log、build/portal_flash.log、build/portal_boot.log；构建目录不会提交。烧录前的旧镜像备份在 build/rollback_pre_portal/。
